# Виртуальная примерочная (3D-аватар по меркам)

Веб-сервис для магазина одежды: пользователь вводит мерки → получает параметрический 3D-аватар → примеряет вещи каталога в разных размерах → видит карту посадки и рекомендацию размера.

## Документы (читать при необходимости, не все сразу)

- `docs/PLAN.md` — **план разработки с чекбоксами. Единый источник правды о прогрессе.**
- `docs/STATUS.md` — текущее состояние: что сделано в последней сессии, что дальше, блокеры.
- `docs/DECISIONS.md` — журнал принятых решений. Не пересматривать без явной просьбы пользователя.
- `docs/ARCHITECTURE.md` — целевая архитектура, модели данных, бюджеты производительности.
- `docs/GIT-WORKFLOW.md` — правила коммитов и ветвления. Соблюдать при любой работе с git.
- `docs/TZ-virtual-fitting-room.md` — исходное ТЗ (бизнес-контекст, полные требования F1–F17).
- `docs/specs/` — детальные спеки этапов (создаются перед началом этапа).

## Регламент работы ИИ (обязательный)

1. **В начале сессии**: прочитай `docs/STATUS.md`, найди в `docs/PLAN.md` первую незакрытую задачу текущего этапа.
2. **Работай по одной задаче за раз.** Не начинай задачи из будущих этапов. Не расширяй скоуп — если видишь нужную работу вне плана, предложи пользователю добавить её в PLAN.md, но не делай молча.
3. **Definition of Done задачи**: код работает (проверено запуском/тестом), чекбокс в PLAN.md проставлен, STATUS.md обновлён.
   - **Коммит — только по явной просьбе пользователя** (см. `docs/GIT-WORKFLOW.md`). По умолчанию изменения готовятся, но не коммитятся.
4. **В конце сессии**: обнови STATUS.md (3–6 строк: сделано / следующий шаг / блокеры). Новые архитектурные решения — строкой в DECISIONS.md.
5. **Контрольные точки (Gate) в PLAN.md закрывает только пользователь** — это визуальная оценка качества. Дойдя до Gate, остановись и попроси пользователя посмотреть результат.
6. **Визуальные проверки**: ты не видишь рендер глазами пользователя. Делай скриншоты/рендеры в `artifacts/` и проси пользователя оценить, когда вопрос эстетический. Технические проверки (морфы экспортировались, FPS, размер файла) делай сам.
7. Перед этапом с пометкой «нужна спека» — сначала напиши `docs/specs/stage-N.md`, согласуй с пользователем, потом код.

## Структура репозитория (целевая)

```
pipeline/   — Python-скрипты для Blender (генерация тела, одежды, экспорт GLB)
web/        — виджет: React + TypeScript + Vite + Three.js (react-three-fiber)
server/     — FastAPI + PostgreSQL (появляется на этапе 5)
assets/     — исходники (.blend) и готовые GLB; крупные файлы — через Git LFS
artifacts/  — рендеры/скриншоты для визуальной проверки (в .gitignore)
docs/       — документация (см. выше)
```

## Технические константы

- Blender запускать headless: `blender --background --python <script>` (путь к blender.exe — в STATUS.md после установки).
- Экспорт: glTF/GLB, морфы тела/одежды — как shape keys → morph targets; имена морфов — `snake_case`, единый словарь в `pipeline/morphs.py`.
- Бюджеты: тело ≤ 4 МБ; вещь ≤ 3 МБ; текстуры ≤ 2K; цель 60 FPS десктоп / 30 FPS мобильный.
- Лицензии ассетов: **только CC0** (MakeHuman community assets). SMPL/SMPL-X не использовать (некоммерческая лицензия). Источник каждого ассета фиксировать в `assets/SOURCES.md`.
- Язык кода и идентификаторов — английский; документация и общение — русский.

## Команды

- **web dev-сервер**: `cd web && npm run dev -- --host 127.0.0.1`
  - На Windows обязательно `--host 127.0.0.1`: по умолчанию Vite биндится только на IPv6 (`::1`), и тогда браузер/playwright по IPv4 получают `ERR_CONNECTION_REFUSED`.
- **web сборка/типы**: `cd web && npm run build` (tsc -b + vite build) · `npm run typecheck`
- **pipeline (Blender headless)**: `& "C:\Program Files\Blender Foundation\Blender 5.1\blender.exe" --background --python <script>`
  - Blender 5.1.2, встроенный Python 3.13.9.
