# ТЗ: Виртуальная примерочная с 3D-аватаром для магазина одежды

Версия: 1.0 (черновик) · Дата: 2026-06-11

---

## 1. Цель продукта

Веб-сервис, встраиваемый в сайт магазина одежды, который:

1. Создаёт персональный 3D-аватар покупателя по введённым параметрам тела (рост, вес, обхваты груди/талии/бёдер и т.д.).
2. Позволяет «надевать» на аватар товары из каталога в разных размерах и визуально оценивать посадку.
3. Рекомендует размер и показывает, где вещь будет тесной/свободной (карта посадки).

Бизнес-цель: снижение возвратов из-за неподошедшего размера и рост конверсии карточки товара.

---

## 2. Важная честная оговорка (прочитать до начала)

Физически точная симуляция ткани на произвольной фигуре в реальном времени в браузере — это уровень CLO3D/Style3D и стоит очень дорого (как в деньгах, так и в R&D). **Практичный и почти бесплатный путь** — комбинация трёх приёмов:

- **Параметрический аватар**: одна базовая 3D-модель тела + морф-таргеты (blend shapes), управляемые мерками пользователя. Никакого ИИ и GPU-сервера не нужно — это чистая математика на клиенте.
- **Одежда, «привязанная» к тем же морфам**: каждая вещь моделируется один раз поверх базового тела и деформируется вместе с ним. Размеры (S/M/L) — это разные меши или разные пресеты морфов одежды.
- **Карта посадки по меркам, а не по физике**: сравниваем обхваты аватара с мерками изделия из размерной таблицы (ease = мерка изделия − мерка тела) и подсвечиваем зоны: красный = тесно, зелёный = по фигуре, синий = свободно. Это даёт 90% бизнес-ценности при 5% сложности симуляции ткани.

Именно этот подход заложен в ТЗ как основной.

## 3. Функциональные требования

### 3.1. Создание аватара
- **F1.** Форма ввода параметров: пол, рост, вес — обязательные; обхват груди, талии, бёдер, длина внутреннего шва, обхват шеи, длина рукава — опциональные (недостающие оцениваются регрессией от роста/веса/пола).
- **F2.** Аватар генерируется и отображается < 2 секунд, без отправки фото (приватность, нет GPU-затрат).
- **F3.** Слайдеры тонкой подстройки фигуры (живот, плечи, бёдра) с мгновенным обновлением модели.
- **F4.** Базовая кастомизация внешности: тон кожи, причёска (5–10 пресетов) — чтобы аватар не был «жутким», но без претензии на портретное сходство. (Фотореалистичное лицо по селфи — опционально, фаза 3, через сторонний SDK.)
- **F5.** Сохранение аватара: гость — в localStorage, залогиненный — в профиле (привязка к аккаунту магазина).

### 3.2. Примерка
- **F6.** Из карточки товара кнопка «Примерить» открывает 3D-вью: аватар в выбранной вещи выбранного размера.
- **F7.** Переключение размеров (S/M/L/...) с обновлением посадки.
- **F8.** Комбинирование: верх + низ + обувь одновременно (послойная система: бельё → низ → верх → верхний слой).
- **F9.** Режим «карта посадки»: heatmap тесно/по фигуре/свободно по зонам (грудь, талия, бёдра, рукав, длина).
- **F10.** Рекомендация размера: «Ваш размер — M» с пояснением («в груди по фигуре, в талии свободно 4 см»).
- **F11.** Вращение/зум камеры, 2–3 пресета поз (стоя, профиль), кнопка «поделиться» (рендер в PNG).

### 3.3. Админка / пайплайн контента
- **F12.** Загрузка 3D-модели вещи (GLB) + привязка к товару каталога + размерная таблица (мерки изделия по размерам).
- **F13.** Валидатор ассетов: проверка полигонажа, текстур, наличия морфов, веса файла.
- **F14.** Статусы: товар «с примеркой» / «только размерная рекомендация» (для вещей без 3D-модели работает только F10 — это важно, т.к. рекомендация размера не требует 3D-контента и покрывает весь каталог сразу).

### 3.4. Интеграция в сайт
- **F15.** Виджет подключается одной строкой `<script>` + `data-product-id` на кнопке, открывается в iframe/модалке (изоляция стилей, безопасность).
- **F16.** REST API: `POST /avatars`, `GET /garments/{id}`, `POST /fit` (расчёт посадки), `GET /recommendation`.
- **F17.** События для аналитики магазина (открыл примерку, сменил размер, добавил в корзину из примерки).

### 3.5. Нефункциональные
- 60 FPS на среднем ноутбуке, ≥ 30 FPS на мобильном среднего класса; вещь ≤ 2–3 МБ (Draco + KTX2).
- Параметры тела — чувствительные данные: хранить только с согласием, давать кнопку удаления (GDPR/152-ФЗ).
- Работает в Chrome/Safari/Firefox/Edge последних 2 версий, iOS Safari обязательно.

### 4.1. Ключевые библиотеки (всё open source)

| Назначение | Библиотека | Лицензия |
|---|---|---|
| 3D-рендер в браузере | Three.js | MIT |
| React-обёртка | @react-three/fiber, @react-three/drei | MIT |
| Сжатие геометрии | Draco (glTF extension) | Apache 2.0 |
| Сжатие текстур | KTX2/Basis | Apache 2.0 |
| Обработка GLB в пайплайне | glTF-Transform | MIT |
| Базовое тело + морфы | MakeHuman / MPFB2 (ассеты CC0) | CC0 — можно в коммерцию |
| Состояние UI | Zustand | MIT |
| Backend | FastAPI + Pydantic / NestJS | MIT |

**Осторожно с SMPL/SMPL-X** (стандартная научная модель тела): она точнее MakeHuman, но лицензия — только некоммерческая; коммерческая лицензия покупается у Meshcapade и стоит ощутимо. Для старта MPFB2/MakeHuman (CC0) — юридически чистый бесплатный вариант.

### 4.2. Как устроен аватар (техническая суть)

1. Базовый меш тела (мужской/женский) с ~30 морф-таргетами: рост, полнота, обхваты по зонам, длины конечностей.
2. Маппинг «мерки → веса морфов»: калибруется один раз — измеряем виртуальной лентой обхваты меша при разных весах морфов и строим обратную функцию (линейная регрессия / lookup-таблица). Это главная инженерная работа MVP.
3. Недостающие мерки достраиваются антропометрической регрессией (открытые датасеты ANSUR II, CAESAR-производные таблицы).

### 4.3. Как устроена «одежда»

1. Вещь моделируется поверх базового тела в нейтральной форме, копирует его скелет (skinning) и **те же морф-таргеты** (переносятся автоматически через surface deform/data transfer в Blender — скриптуется).
2. Размер S/M/L = отдельный набор морфов одежды (или отдельный меш), соответствующий меркам изделия из размерной таблицы.
3. При примерке: тело и одежда получают веса морфов тела → одежда «следует» за фигурой; поверх — шейдерная маска прятания тела под одеждой (anti-clipping).
4. Карта посадки: чистая математика на мерках (см. §2), рендерится vertex-color оверлеем.

**Стоимость контента — главная статья расходов в этой модели**: каждая вещь = 2–6 часов работы 3D-художника (или генерация из лекал в CLO3D + ретопология). Закладывайте ~1500–5000 ₽/вещь на аутсорсе либо своего художника. Для MVP достаточно 5–10 вещей.

## 5. Альтернатива: готовые SDK (если не хочется делать аватар самим)

| Сервис | Что даёт | Цена (порядок) | Минусы для нашей задачи |
|---|---|---|---|
| **Avaturn** | Аватар по селфи, реалистичный | фритир для теста, коммерция от ~$200–300/мес | Тело не строится по меркам — посадку не оценить |
| **MetaPerson (Avatar SDK)** | Аватар по фото + параметры тела | поштучно ~$0.1–0.3/аватар или план от ~$100/мес | Морфы тела ограничены, нужна интеграция одежды |
| **Ready Player Me** | Бесплатные стилизованные аватары | бесплатно/дёшево | Игровой стиль, тело вообще не по меркам — для примерки не подходит |
| **3DLOOK / Fit:Match** | Замер тела по 2 фото + size rec | B2B, сотни–тысячи $/мес | Дорого, это конкурент, а не компонент |
| **CLO3D / Style3D** | Физика ткани, цифровые двойники одежды | от ~$50/мес за место (инструмент дизайнера) | Это инструмент создания контента, не runtime |

**Вывод:** ни один дешёвый SDK не решает связку «тело по меркам + примерка» целиком. SDK имеет смысл только как доп. фича «лицо по селфи» (фаза 3). Ядро выгоднее делать своё — оно бесплатно в runtime.

## 6. Ответ на вопрос о цене

**Можно ли бесплатно?** Сам runtime — да: параметрический аватар считается на клиенте, GPU-сервер не нужен, весь софт open source. Платить придётся за:

| Статья | MVP | Прод |
|---|---|---|
| Хостинг backend (VPS/Fly.io/Railway) | $0–10/мес | $20–50/мес |
| Хранилище + CDN (Cloudflare R2) | $0 (фритир) | $5–20/мес |
| 3D-контент одежды | 5–10 вещей × 1500–5000 ₽ | по каталогу |
| CLO3D (опционально) | — | ~$50/мес |
| SDK «лицо по селфи» (опц., фаза 3) | — | ~$100+/мес |

Т.е. **MVP реально уложить в ~$10–30/мес инфраструктуры + разовые затраты на 3D-модели одежды**. Генерация аватара ничего не стоит за штуку — в отличие от photo-to-3D сервисов.

## 7. План работ

### Фаза 0 — Прототип (1–2 недели)
- Базовое тело MPFB2 c 5 морфами (рост/вес/грудь/талия/бёдра) в Three.js.
- 1 футболка в 3 размерах, следящая за морфами.
- Цель: убедиться, что качество визуала приемлемо. **Go/No-Go точка.**

### Фаза 1 — MVP (4–8 недель)
- Полный маппинг мерок → морфы + регрессия недостающих мерок.
- Виджет (iframe + script-тег), форма параметров, сохранение аватара.
- Карта посадки + рекомендация размера (F9, F10) — работает и без 3D-модели вещи.
- Пайплайн контента в Blender (скрипт переноса морфов) + 5–10 вещей.
- Backend: FastAPI + Postgres + R2, API из §3.4.

### Фаза 2 — Продукт (4–6 недель)
- Послойная примерка (верх+низ), позы, шаринг PNG.
- Админка загрузки ассетов с валидатором.
- Аналитика событий, A/B-хуки, оптимизация мобильного FPS.

### Фаза 3 — Улучшения (по результатам метрик)
- Лицо по селфи (MetaPerson/Avaturn SDK).
- Псевдофизика ткани (vertex springs / XPBD на GPU через three.js compute) для «живости» подола/рукавов.
- AR-режим (WebXR) «посмотреть на себе через камеру».

## 8. Риски

| Риск | Митигация |
|---|---|
| «Эффект зловещей долины» — аватар отпугивает | Слегка стилизованный рендер (matcap/toon-lite), нейтральное лицо, фаза 0 как фильтр |
| Стоимость 3D-контента растёт с каталогом | Запускать size-recommendation на весь каталог (без 3D), 3D — только для топ-товаров |
| Пользователи не знают свои мерки | Регрессия от рост/вес/пол + иллюстрированная инструкция «как измерить»; опц. замер по фото позже |
| Точность посадки ≠ реальность (ткань тянется) | Учитывать эластичность ткани коэффициентом в формуле ease (поле в админке) |
| Лицензии моделей тела | Только CC0 (MPFB2) или купленная коммерческая; SMPL без лицензии не использовать |
| iOS Safari память/FPS | Лимит 2–3 МБ на вещь, KTX2, один источник света, без постпроцессинга на мобиле |

## 9. Команда для MVP

- 1 фронтенд с опытом Three.js (ключевая роль) — full-time.
- 1 бэкенд (FastAPI/Node) — part-time.
- 1 3D-художник (Blender, желательно знакомый с одеждой/CLO) — part-time/аутсорс.

Реалистичный срок MVP силами 1.5–2 человек: **2–3 месяца**.
