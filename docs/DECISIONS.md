# Журнал решений (ADR-лайт)

> Формат: дата · решение · почему. Решения не пересматриваются молча — только по явной просьбе пользователя, со строкой «отменено: причина».

- **2026-06-11 · Параметрический аватар вместо photo-to-3D.** Тело = базовый меш + морф-таргеты, мерки → веса морфов на клиенте. Почему: бесплатно в runtime (нет GPU-сервера и платных API), мгновенно, приватно (фото не нужны).
- **2026-06-11 · База тела — MakeHuman / MPFB2 (ассеты CC0).** Почему: легально для коммерции без покупки лицензии. SMPL/SMPL-X запрещены к использованию — некоммерческая лицензия.
- **2026-06-11 · Посадка считается по меркам (ease), не физикой ткани.** ease = мерка изделия − мерка тела, с коэффициентом эластичности; heatmap по зонам. Почему: 90% бизнес-ценности при доле сложности cloth-симуляции; симуляция в браузере на произвольной фигуре — нереалистичный R&D.
- **2026-06-11 · Одежда — proxy-меши, привязанные к морфам тела.** Размеры S/M/L — пресеты морфов одежды под мерки изделия. Источник вещей: CC0-ассеты MakeHuman community, дыры закрываются процедурной генерацией (Blender Python), ручная работа — крайний случай.
- **2026-06-11 · Контентный конвейер — шаблоны + 2 фото.** Геометрия из параметрического шаблона по размерной таблице; фото фронт/спинка — только текстура (UV-проекция, блендинг на боках). Фотограмметрия — опция для флагманских товаров, не базовый путь.
- **2026-06-11 · Стек.** web: Vite + React + TS + Three.js (react-three-fiber). pipeline: Python + headless Blender. server: FastAPI + PostgreSQL + MinIO (появляется на этапе 5; до того — localStorage). Виджет: script-тег + iframe + postMessage.
- **2026-06-11 · Рекомендация размера работает без 3D-модели вещи.** Расчёт по меркам покрывает весь каталог сразу; 3D-примерка — для товаров с готовым ассетом. Почему: контент — главная статья расходов, нельзя делать его блокером ценности.
- **2026-06-12 · Посадка и рекомендация размера — по меркам (`web/src/fit.ts`).** На зону: `ease = обхват изделия − тела`, `effective = ease + elasticity·7`. **«Тесно» = `effective < 2 см` (физика, не зависит от профиля); «свободно» = `effective > loose[fit]`.** Профиль задаёт идеал по груди и порог loose (oversize: ideal 18, loose 40; regular: 10/18; slim: 4/12; relaxed: 15/28). У типа вещи есть главная зона (футболка → грудь). **Рекомендация:** среди размеров, где главная зона не тесна, — ближайший к идеалу профиля (при равенстве меньший); если все тесны — самый большой + «маловат». Почему так (после фидбэка «везде тесно»): порог «тесно» развязан с профилем, а рекомендация целится в задуманную посадку — средний человек получает нормальный размер. Работает **без 3D-вариантов по размерам** (чисто числа, покрывает весь каталог). `garment.json`: тип/пол/fit/эластичность/размеры (обхваты изделия; бренд шлёт полуобхваты → ×2). 3D-карта посадки — задача 4.6.
  - **Данные опираются на EN 13402-3 / ISO 8559** (а не выдуманы): размерные таблицы = центр диапазона тела по EN + проектный припуск (oversize +18); пороги ease — из практики кроя. Проверено: рекомендация совпадает с EN-размером тела (грудь 86→S, 94→M, 102→L…). Источники — `assets/SOURCES.md`. Тай-брейк при равенстве: oversize/relaxed → больший размер («size up»), slim/regular → меньший.
- **2026-06-13 · Женская грудь — скромнее по умолчанию.** Фидбэк: грудь крупновата/заострена для среднего обхвата. Нейтральный cupsize 0.55→0.35, firmness 0.45 → натуральная грудь при обхвате ~80 см; ввод большего обхвата груди увеличивает её морфом. Потребовало пересборки женского тела → рекалибровки (нейтр. обхват груди 82.5→80) → женской одежды.
- **2026-06-12 · Два пола — отдельные тела и одежда.** Тело: макрос пола MakeHuman (жен. gender 0.1 + cupsize 0.55, муж. gender 0.9 + cupsize 0) → `gen_body.py --gender` → отдельные GLB. Одежда: своя CC0-вещь на пол (жен. `joepal_crude_t-shirt_female`, муж. `elvs_crude_t-shirt_male`, оба из пака shirts01), примеряется на тело своего пола. Топология базового меша одна → одежда/морфы совместимы.
- **2026-06-12 · Ввод по меркам, а не ползунками.** UI — форма: пол + рост/вес/обхваты груди/талии/бёдер. Морфы считаются линейно: `influence = (мерка − neutral)/perUnit`, где neutral/perUnit измерены в Blender (`calibrate.py`: обхват = периметр выпуклой оболочки среза торса на доле роста; рост = габарит по Z). Вес → морф полноты через отклонение от BMI-22. Вторичные морфы (muscle/shoulders/neck/arm/thigh) = 0, правятся в свёрнутой «Тонкой настройке». Ползунки демонтированы из основного UI. Точность обхватов — приближённая (выпуклая оболочка), уточнение ≤2см вынесено в этап 3 (задача 3.6).
- **2026-06-11 · Git: Conventional Commits + привязка к задачам PLAN.** Заголовок коммита английский (`type(scope): … (task-id)`), тело можно по-русски, футер `Co-Authored-By` при участии ИИ. Ветвление: работа в рабочих ветках, `main` всегда собирается и отражает пройденные Gate. Один коммит — одна логическая единица. Полные правила — `docs/GIT-WORKFLOW.md`. Почему: читаемая история, каждый коммит трассируется к задаче, `main` всегда демонстрабелен.
- **2026-06-12 · Одежда — готовые CC0-ассеты MakeHuman (MHCLO), морфы по ближайшей вершине.** Аккуратная одежда берётся из готовых вещей с правильной топологией (источник: CC0-паки MakeHuman community, напр. `shirts01`). MPFB примеряет MHCLO на тело (`add_mhclo_asset`), затем морфы тела переносятся в shape keys одежды по ближайшей вершине тела (KD-дерево) — предсказуемо, без протыканий. Почему не Surface Deform: сглаживает деформацию, одежда недо-раздувается и тело протыкает её на полных фигурах. Почему не процедурная оболочка/симуляция: рваные края, не похоже на настоящую вещь. `pipeline/gen_mhclo_garment.py`. Это целевой метод привязки одежды каталога (этап 2).
- **2026-06-12 · Физика ткани: нейтральная драпировка из cloth-симуляции + ЛИНЕЙНЫЕ морфы по ближайшей вершине.** Выбран бесплатный путь «Blender-сим → морфы». Итоговый рецепт (`pipeline/sim_morph_garment.py`): стартовая вещь = MHCLO-ассет + припуск (ease) → ОДНА cloth-симуляция на нейтральном теле даёт свободную драпировку (Basis); морфы = линейный перенос дельт тела по ближайшей вершине. Runtime в браузере — дешёвые morph targets, мгновенно, мобайл-френдли.
  - **2026-06-13 · Реализм одежды — PBR-материал + CC0-карты ткани.** Одежда: `MeshPhysicalMaterial` со sheen (ворсистость хлопка) + настоящие CC0-карты трикотажа cotton_jersey (Poly Haven): diffuse/normal/roughness, тайл по UV. Заменили процедурную нормаль и плоский цвет → читается как ткань, не пластик. Следующий рычаг (выбран пользователем) — запечённые normal-map складки из высокоплотной симуляции (отдельный bake-пайплайн в Blender; для совмещения с тайл-нормалью нужен detail-normal через onBeforeCompile). `web/src/AvatarViewer.tsx fabricMaterial()`.
  - **2026-06-13 · Усиление физики футболки:** cloth-сим с self-collision (складки не протыкаются) и air-damping; **Solidify (толщина ткани ~6 мм)** после сим до запекания морфов → края не бумажные. Бюджет: subdiv 1. 8520 верт., ~0.88 МБ.
    - Тюнинг против «странных складок» (фидбэк): меньше слабины (inflate 0.05→0.035), выше жёсткость на растяжение/сжатие (25/25), шире изгиб (0.6) — убрало горизонтальную складку-кольцо под грудью.
    - Фидбэк «футболка парит над плечами»: раздув (inflate) сделан с вертикальным затуханием — у плеч/ворота 0 (вещь садится на тело), нарастает к низу. Раньше равномерный раздув приподнимал весь верх, а пин держал его над плечами.
    - Фидбэк «странные складки на плечах»: резкая линейная граница раздува у пройм давала сборку. Переход сделан плавным (smoothstep) и смещён ниже (t 0.18→0.55): плечи+грудь по телу, слабина только ниже груди.
    - Фидбэк «странные складки на плечах и груди» (повтор): зажал ткань (bending 0.6→1.5, tension/compression 30/30 → широкие гладкие складки) и **отключил self-collision** — на грубой сетке оно давало мелкие комки на плечах/под грудью.
    - Фидбэк «складки на спине»: ткань уходила в поясничный прогиб и собиралась. Ещё жёстче (bending 3.5, tension/compression 40/40 → почти гладкая драпировка) + больший зазор столкновения (distance_min 0.008) — вещь мягко перекрывает вогнутости (поясница, под грудью), а не сминается в них. Текущая философия: чистая гладкая посадка важнее обилия складок.
  - **Важный урок (тупик):** запекать морфы из НЕЗАВИСИМЫХ per-morph симуляций нельзя — дельты нелинейны и при сложении в браузере (несколько морфов разом) рвут меш «в клочья». Линейный перенос по ближайшей вершине блендится чисто. Поэтому драпировка одна на все фигуры (форма свободная и стабильная), а не пересимулируется per-morph.
  - **Live-физика в браузере (Ammo/Jolt) отклонена:** для виджета плохой UX (тряска/ресеттл при смене мерок) и риск FPS на мобильных. Marvelous Designer/CLO (~$50/мес) — опция для топ-качества авторинга позже.
