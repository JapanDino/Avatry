# План разработки: от пустого репозитория до рабочей версии

> **Правила ведения файла.** Это единый источник правды о прогрессе. ИИ берёт первую незакрытую задачу текущего этапа, делает её, проставляет `[x]` и обновляет `docs/STATUS.md`. Чекбоксы `**Gate**` закрывает только пользователь после визуальной оценки. Новые задачи добавляются только по согласованию с пользователем (помечать `(added)`), удалённые — зачёркивать, не стирать.

Легенда: `[ ]` не начато · `[x]` готово · `Gate` — контрольная точка пользователя.

## Этап 1. Параметрическое тело (proof of concept)

Цель: тело MakeHuman с морфами крутится в браузере и меняется слайдерами в реальном времени.

- [ ] 1.1. Установить Blender (последний LTS), зафиксировать путь к `blender.exe` в STATUS.md
- [ ] 1.2. Установить аддон MPFB2 + базовые ассеты тела; проверить генерацию тела в headless-режиме
- [ ] 1.3. Скрипт `pipeline/gen_body.py`: генерирует базовое тело (муж. и жен.) с shape keys: `height`, `weight`, `chest`, `waist`, `hips`
- [ ] 1.4. Скрипт `pipeline/export_glb.py`: экспорт GLB с морфами; проверить программно, что морфы присутствуют в файле и вес ≤ 4 МБ
- [ ] 1.5. Рендер-превью тела в `artifacts/` (нейтральная поза, 3 ракурса) для визуальной проверки
- [ ] 1.6. `web/`: компонент `<AvatarViewer>` — загрузка GLB, свет, камера, пол; нейтральный матовый материал кожи
- [ ] 1.7. `web/`: панель из 5 слайдеров, привязанных к morph target influences; изменения применяются без перезагрузки модели
- [ ] 1.8. Проверка крайних значений: все 5 морфов на min/max в комбинациях, рендеры в `artifacts/extremes/`
- [ ] **Gate 1 (пользователь):** фигура на слайдерах выглядит адекватно, без уродств на крайних значениях

Цель: одетый аватар, одежда следует за фигурой. Здесь решается Go/No-Go всего проекта.

- [ ] 2.1. Отобрать в MakeHuman community assets 2 вещи под CC0 (футболка + штаны); скачать, записать в `assets/SOURCES.md`
- [ ] 2.2. Скрипт `pipeline/fit_garment.py`: надеть proxy-одежду на тело, перенести морфы тела на одежду, экспорт GLB
- [ ] 2.3. `web/`: слой одежды поверх тела, морфы тела и одежды двигаются синхронно от одних слайдеров
- [ ] 2.4. Anti-clipping: маска скрытия тела под одеждой (вершинная маска или material clipping); проверить на крайних морфах
- [ ] 2.5. Прогон матрицы: 2 вещи × 5 морфов × крайние значения → рендеры в `artifacts/`; починить найденные протыкания

## Этап 3. Мерки вместо слайдеров

Цель: пользователь вводит свои цифры — получает свою фигуру. Нужна спека: `docs/specs/stage-3.md`.

- [ ] 3.1. Спека: список входных мерок, единицы, диапазоны валидации, формат маппинга
- [ ] 3.2. Скрипт `pipeline/measure.py`: виртуальная измерительная лента — обхваты груди/талии/бёдер и рост меша при заданных весах морфов (срез меша плоскостью → периметр выпуклой оболочки)
- [ ] 3.3. Калибровка: прогнать сетку комбинаций морфов, построить таблицу «веса морфов → мерки», инвертировать (lookup + интерполяция); сохранить как JSON для клиента
- [ ] 3.4. Регрессия недостающих мерок от пола/роста/веса (коэффициенты по открытым антропометрическим таблицам); зафиксировать источник в DECISIONS.md
- [ ] 3.5. `web/`: форма ввода (пол, рост, вес обязательные; обхваты опциональные) с валидацией диапазонов
- [ ] 3.6. Тест точности: задать мерки → построить тело → измерить лентой → расхождение ≤ 2 см по каждому обхвату
- [ ] 3.7. Сохранение аватара в localStorage; слайдеры остаются как «тонкая подстройка» поверх мерок
- [ ] **Gate 3 (пользователь):** ввести свои реальные мерки и оценить похожесть фигуры

## Этап 4. Размеры, посадка, рекомендация

Цель: ядро бизнес-ценности — heatmap посадки и «ваш размер M». Нужна спека: `docs/specs/stage-4.md`.

- [ ] 4.1. Спека: модель данных размерной таблицы (мерки изделия по размерам), коэффициенты эластичности ткани, пороги ease для зон тесно/ок/свободно
- [ ] 4.2. Формат `garment.json` рядом с GLB: тип, размеры, мерки изделия, эластичность
- [ ] 4.3. Пайплайн: для каждой вещи генерировать варианты S/M/L (морфы одежды под мерки изделия из таблицы)
- [ ] 4.4. Расчёт посадки (модуль на TypeScript, позже переедет на сервер): ease по зонам с учётом эластичности
- [ ] 4.5. `web/`: переключатель размеров в просмотрщике
- [ ] 4.6. `web/`: режим «карта посадки» — вершинный цветовой оверлей по зонам (красный/зелёный/синий)
- [ ] 4.7. Рекомендация размера с текстовым пояснением («в груди по фигуре, в талии свободно 4 см»)
- [ ] 4.8. Ручная валидация: 3 контрольные фигуры × 2 вещи — рекомендации согласуются со здравым смыслом и размерной таблицей
- [ ] **Gate 4 (пользователь):** посадка и рекомендации правдоподобны

## Этап 5. Бэкенд и персистентность

Цель: данные переезжают с клиента на сервер. До сих пор всё жило в localStorage — это было осознанно.

- [ ] 5.1. `server/`: FastAPI + SQLAlchemy + Alembic; docker-compose с PostgreSQL и MinIO для локальной разработки
- [ ] 5.2. API: `POST/GET/DELETE /avatars` (анонимный ID + опциональная привязка к пользователю магазина)
- [ ] 5.3. API: `GET /garments`, `GET /garments/{id}` (метаданные + ссылки на GLB в хранилище)
- [ ] 5.4. API: `POST /fit` — перенос расчёта посадки на сервер (источник правды), клиентский расчёт остаётся для мгновенного отклика
- [ ] 5.5. Удаление данных по запросу (приватность): endpoint + кнопка в UI
- [ ] 5.6. Тесты API (pytest + httpx), запуск одной командой
