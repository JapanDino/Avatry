# Спека: Размеры, посадка, рекомендация (этап 4 / «этап 2» в обсуждении)

Цель: для вещи каталога с размерной таблицей и по меркам пользователя показать
посадку по зонам (тесно / по фигуре / свободно), рекомендовать размер и (далее)
подсветить карту посадки на аватаре.

Это ядро бизнес-ценности: снижает возвраты из-за размера. Важно: **рекомендация
размера работает и без 3D-модели вещи** — только по меркам (покрывает весь каталог).

## Данные

### garment.json (на товар, рядом с GLB)
```json
{
  "id": "tee-basic",
  "type": "tshirt",
  "gender": "male",            // male | female | unisex
  "fit": "oversize",           // slim | regular | oversize — задаёт целевой ease
  "elasticity": 0.15,          // 0 = не тянется (хлопок), 1 = сильно тянется
  "sizes": [
    { "label": "S/M", "glb": "top_male.glb",
      "garment": { "chest": 112, "waist": 110, "hips": 112, "length": 70, "sleeve": 22 } },
    { "label": "M/L", "glb": "top_male.glb",
      "garment": { "chest": 120, "waist": 118, "hips": 120, "length": 73, "sleeve": 23 } }
  ]
}
```
- `garment.*` — мерки **изделия в обхвате** (см). Бренд присылает плоские мерки
  (полуобхваты) по чек-листу → пайплайн умножает на 2 при импорте. Длины — как есть.
- Зоны обхватов: `chest, waist, hips`. Длины: `length, sleeve` (информативно).

### Мерки тела
Берём из формы (этап 3): `chest, waist, hips` (обхваты), `height`. Уже сравнимы
с обхватами изделия напрямую.

## Расчёт посадки (итоговые критерии)

Для каждой зоны z ∈ {chest, waist, hips}:
```
ease_z      = garment_z − body_z                         // запас ткани, см
effective_z = ease_z + elasticity * STRETCH_ALLOWANCE    // тянучая ткань «прощает» дефицит
```
`STRETCH_ALLOWANCE = 7` см (при elasticity 1 изделие может быть на 7 см уже тела).

**Класс зоны — «тесно» не зависит от профиля** (это физическая носибельность),
а «свободно» — зависит:
```
class_z =
   effective_z < TIGHT_MIN (=2 см)   → "tight"   (тесно, красный)
   effective_z > LOOSE[fit]          → "loose"   (свободно, синий)
   иначе                             → "good"    (по фигуре, зелёный)
```
Профиль задаёт целевой запас по груди `ideal` и порог `loose` (см):
| fit       | ideal | loose |
|-----------|-------|-------|
| slim      | 4     | 12    |
| regular   | 10    | 18    |
| relaxed   | 15    | 28    |
| oversize  | 18    | 40    |

### Главная зона и рекомендация
- У каждого типа вещи есть **главная зона**: футболка/худи/платье → грудь;
  штаны/шорты → талия; юбка → бёдра. Остальные зоны информативны.
- **Рекомендация:** среди размеров, где главная зона НЕ «тесно», берём ближайший
  к `ideal` профиля (при равенстве — меньший = более прилегающий, можно взять
  больше для оверсайза). Если все размеры тесны в главной зоне — самый большой +
  «даже {XL} маловат».
- Текст: «Ваш размер — S: по груди запас ~19 см» (+ «— сидит свободно», если loose).
- Почему так: целимся в задуманную посадку (oversize ≈ +18 см по груди), «тесно»
  ставим только при реальном дефиците ткани, поэтому средний человек получает
  нормальный размер, а не «тесно везде».

## UI (web)
- Выбор товара (пока 1 демо-вещь с таблицей) + кнопки размеров (S/M, M/L).
- Панель посадки: рекомендуемый размер выделен; по зонам — статус (тесно/ок/свободно)
  с цветом; текстовое пояснение.
- (Этап 4b) Карта посадки на аватаре: подсветить зоны тела/одежды цветом класса
  (вершинные цвета по Z-зонам). Сначала 2D-панель, 3D-heatmap — следом.

## Открытые вопросы / решения по умолчанию
- **Реальных таблиц бренда пока нет** (чек-лист отправлен). Делаем на синтетической
  таблице oversize-футболки; при получении реальных — подставляем.
- Длина/рукав в посадку v1 не входят (нужна длина торса/руки тела — оценка от роста);
  пока только обхваты груди/талии/бёдер. Длины показываем информативно.
- Пороги `fit` подбираем эмпирически на демо, потом калибруем.
